# Структура frontend

`src/App.tsx` отвечает за запуск, текущую сессию и выбор экрана авторизации или рабочего пространства. `src/pages/Workspace.tsx` хранит рабочее состояние, маршрутизацию по hash и подтверждение ухода при несохранённых изменениях. Список допустимых маршрутов находится в `src/navigation/routes.ts`.

Страницы расположены в `src/pages`. Большие сценарии разделены по ответственности: шаги создания презентации находятся в `src/pages/wizard`, вкладки профиля — в `src/pages/profile`, содержимое режимов входа — в `src/components/auth/AuthFlowContent.tsx`. Состояние и запросы остаются у родительских страниц; дочерние компоненты получают данные и обработчики через типизированные props.

`src/api.ts` сохраняет единый публичный объект `api`. Его методы реализованы по областям в `src/api`; общий `client.ts` управляет HTTP-запросами и CSRF-токеном. При добавлении метода расширяйте соответствующий модуль, не создавая второй HTTP-клиент.

Порядок CSS в `src/main.tsx` является частью каскада. Файл `workspace.css` разделён на `workspace-foundations.css`, `workspace-creation.css`, `workspace-pages.css` и `workspace-responsive.css` в прежнем порядке правил. Стили слайдов и их содержимое не зависят от этого разбиения. Все стили импортируются централизованно: загрузка route-чанков не меняет каскад.

Проверки: `npm run build` (TypeScript и production Vite), `npm test`, `npm run test:e2e` (требует Python-окружения backend из конфигурации Playwright).

## Оптимизация фронтенда 18 октября 2026

Рабочее пространство и страницы загружаются через `React.lazy`. `WorkspacePage` запускает прежние анимации после загрузки страницы. Статичная `TemplateCover` отделена от анимированной `TemplateCard`; ScrollTrigger регистрируется в отдельном модуле и не входит в начальную загрузку экрана входа. Three.js остаётся отложенным, все 3D-сцены сохранены.

Запрос текущей сессии выполняется при запуске. Обычные hash-переходы больше не обновляют сессию и корневое состояние; подтверждение почты, восстановление пароля и событие `session-expired` продолжают обрабатываться. Удалены неиспользуемые props `Shell` и недостижимый обработчик поиска в навигационной оболочке; поиск внутри каталога сохранён.

`SlidePreview` и `TemplateCover` пропускают рендер при неизменных данных. Геометрия маркеров аудита кешируется при наведении; список каталога сохраняет ссылку при изменении избранного в общем каталоге, что предотвращает перезапуск GSAP. Индикатор навигации не обновляет состояние при прежней геометрии.

Обработчики указателя в карточках и WebGL-сценах объединяют события до следующего кадра. Размер WebGL-буфера не пересоздаётся при прежних размерах и DPR; задержка между отдельными взаимодействиями не считается медленным кадром. Прозрачные дальние карточки карусели получают конечное состояние без tween. RAF и обработчики очищаются при размонтировании. Потеря WebGL-контекста экрана входа включает прежнюю HTML-обложку. Длительности, easing и координаты анимаций не изменены.

Из CSS удалена повторная декларация Manrope; остальной production CSS побайтно совпадает с исходным. Добавлен preload существующего шрифта и асинхронное декодирование изображений; дальние обложки используют native lazy loading. Все runtime-зависимости используются, новые зависимости не добавлены. В TypeScript включены `noUnusedLocals` и `noUnusedParameters`.

## Второй этап загрузка и доставка ресурсов

`npm run build` после Vite запускает `scripts/precompress.mjs`: создаются `.br` и `.gz` только для текстовых файлов, которые действительно уменьшаются. При повторном запуске устаревшие представления удаляются. `backend/app/http_assets.py` выбирает представление по `Accept-Encoding`, сохраняет исходный MIME и `Vary`, различает ETag вариантов и не использует сжатую копию старее оригинала. Range-запросы получают исходный файл. Сжатие статики выполняется при сборке, а не на каждом запросе.

Версионированные Vite-ресурсы имеют `public, max-age=31536000, immutable`; HTML — `no-store`, остальные публичные ресурсы — `no-cache`. Приватные thumbnail проверяют пользователя до ETag и возвращают `304` без тела при совпадении. Ошибки и остальные API сохраняют `no-store`. JSON каталога и выбранных маршрутов презентаций сжимается стандартным gzip уровня 3; авторизация и бинарные экспорты исключены. URL, поля и права доступа не менялись.

`src/assets/Manrope.woff2` получен из исходного TTF без сокращения символов и начертаний. Сверены cmap, метрики hmtx и ось веса; исходный TTF и OFL сохранены. CSS и preload ссылаются на один файл, который Vite именует по содержимому.

`src/navigation/pageLoaders.ts` объединяет загрузчики для `React.lazy` и предзагрузки по наведению/фокусу. Импорт не монтирует страницу и не запускает её API-запросы; при Save-Data и 2G спекулятивная загрузка отключена. Экран входа и Workspace отменяют незавершённую загрузку каталога и восстановления проекта при размонтировании. HTML-обложки и WebGL-текстуры используют одинаковый CORS-режим `anonymous`: браузер объединяет обращения к одной миниатюре, не занимая соединения повторными загрузками.

При повторе демонстрации `SlideScene` перезапускает существующий GSAP timeline с прежними начальными параметрами. Renderer, геометрия и текстуры остаются в той же сцене; при уходе со страницы они освобождаются как прежде. Тест проверяет сохранение canvas/текстур и изменение изображения после повтора.

Добавлены `backend/tests/test_http_assets.py`, `frontend/tests/precompress.test.mjs`, `frontend/e2e/loading.spec.ts`; `DECKLY_E2E_BASE_URL` позволяет запускать существующие E2E на Docker-интерфейсе. Повторяемый замер загрузки находится в `frontend/scripts/profile-browser.mjs`.

## Обновление демонстрации сборки

Режим `assembly` получил отдельное оформление, не затрагивающее сцену `hero` на главной. Три части одного изображения — заголовок, иллюстрация и данные — за семь секунд собираются в цельный слайд, затем раскрывается веер из трёх демонстрационных слайдов. Части вырезаются из той же canvas-текстуры, которая становится готовым слайдом: переход не подменяет содержание. Manrope и фирменный синий сохранены. Светлые края, мягкие тени и фоновые орбиты выполнены без постобработки и новых зависимостей.

`assemblyArtwork.ts` рисует текстуры при инициализации и после готовности шрифта, с защитой от обновления после dispose. `SlideScene.tsx` переиспользует геометрию, renderer и timeline при повторе; скрытые части исключаются из отрисовки. Скругления созданы небольшим BufferGeometry без подключения triangulation-модуля. Для узкого контейнера пересчитываются кадрирование и размах веера; мобильная высота сцены уменьшена до 280 px. `AssemblyPoster.tsx` показывает тихую финальную композицию при reduced motion или отсутствии WebGL. Устаревшая `fragmentTexture` удалена из `slideTexture.ts`.

Проверки: production build/TypeScript, 14 frontend unit, Prettier и 13 production E2E (`demo-assembly`, `loading`, `spatial-experience`) проходят. Дополнительно сняты фазы появления, сборки и финала, обе темы, мобильный вид и статичный poster; проверен повтор и освобождение текстур.
