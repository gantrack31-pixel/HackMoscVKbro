# Структура frontend

`src/App.tsx` отвечает за запуск, текущую сессию и выбор экрана авторизации или рабочего пространства. `src/pages/Workspace.tsx` хранит рабочее состояние, маршрутизацию по hash и подтверждение ухода при несохранённых изменениях. Список допустимых маршрутов находится в `src/navigation/routes.ts`.

Страницы расположены в `src/pages`. Большие сценарии разделены по ответственности: шаги создания презентации находятся в `src/pages/wizard`, вкладки профиля — в `src/pages/profile`, содержимое режимов входа — в `src/components/auth/AuthFlowContent.tsx`. Состояние и запросы остаются у родительских страниц; дочерние компоненты получают данные и обработчики через типизированные props.

`src/api.ts` сохраняет единый публичный объект `api`. Его методы реализованы по областям в `src/api`; общий `client.ts` управляет HTTP-запросами и CSRF-токеном. При добавлении метода расширяйте соответствующий модуль, не создавая второй HTTP-клиент.

Порядок CSS в `src/main.tsx` является частью каскада. Файл `workspace.css` разделён на `workspace-foundations.css`, `workspace-creation.css`, `workspace-pages.css` и `workspace-responsive.css` в прежнем порядке правил. Стили слайдов и их содержимое не зависят от этого разбиения. Все стили импортируются централизованно: загрузка route-чанков не меняет каскад.

Проверки: `npm run build` (TypeScript и production Vite), `npm test`, `npm run test:e2e` (требует Python-окружения backend из конфигурации Playwright).

## Оптимизация фронтенда 18 октября 2026

Рабочее пространство и страницы загружаются через `React.lazy`. `WorkspacePage` запускает прежние анимации после загрузки страницы. Статичная `TemplateCover` отделена от анимированной `TemplateCard`; ScrollTrigger регистрируется в отдельном модуле и не входит в начальную загрузку экрана входа. Three.js остаётся отложенным, все 3D-сцены сохранены.

Запрос текущей сессии выполняется при запуске. Обычные hash-переходы больше не обновляют сессию и корневое состояние; подтверждение почты, восстановление пароля и событие `session-expired` продолжают обрабатываться. Удалены неиспользуемые props `Shell` и недостижимый обработчик поиска в навигационной оболочке; поиск внутри каталога сохранён.

`SlidePreview` и `TemplateCover` пропускают рендер при неизменных данных. Геометрия маркеров аудита кешируется при наведении; список каталога сохраняет ссылку при изменении избранного в общем каталоге, что предотвращает перезапуск GSAP. Индикатор навигации не обновляет состояние при прежней геометрии.

Обработчики указателя в карточках и WebGL-сценах объединяют события до следующего кадра. Размер WebGL-буфера не пересоздаётся при прежних размерах и DPR; задержка между отдельными взаимодействиями не считается медленным кадром. Прозрачные дальние карточки карусели получают конечное состояние без tween. RAF и обработчики очищаются при размонтировании. Потеря WebGL-контекста экрана входа включает прежнюю HTML-обложку. Длительности, easing и координаты анимаций не изменены.

Из CSS удалена повторная декларация Manrope; остальной production CSS побайтно совпадает с исходным. Добавлен preload существующего шрифта и асинхронное декодирование изображений; дальние обложки используют native lazy loading. Все runtime-зависимости используются, новые зависимости не добавлены. В TypeScript включены `noUnusedLocals` и `noUnusedParameters`.

### Результаты проверок и ограничения

- `npm run build`: TypeScript и production Vite build проходят. Проверки неиспользуемых символов включены постоянно.
- `npm test`: 12/12 проходят. Prettier для изменённой реализации и `git diff --check` проходят. Отдельного ESLint-конфига и lint-script в проекте нет.
- Playwright: 36/38 сценариев проходят при запуске каждого spec-файла с новой временной БД. Дополнительно прошли два временных сценария снятия эталонных скриншотов; они удалены из рабочего дерева. Проверены создание, формы, редактирование, история, сохранение, аудит, экспорт, AI-помощник, отмена операций, мобильная галерея, поиск, избранное, выбор шаблона, темы, fallback WebGL, возврат сцены после прокрутки и остановка рендера в покое. В штатных пространственных сценариях проверки `pageerror` и `console.error` проходят.
- Два старых теста обращались к отсутствующим в исходном интерфейсе элементам: обновлены селекторы экрана входа и мобильной галереи. Проверка контраста теперь выполняется в обеих темах; мобильный сценарий дополнен выбором шаблона для создания.
- 12 сравнений снимков до/после: вход, главная, каталог, редактор, аудит и завершение при 1440 и 390 px, reduced motion. 10 полностью совпадают по пикселям. В редакторе и аудите на 1440 px различается только текст нативного `select` в области 99×15 и 113×15 px; остальная картинка совпадает. Снимки анимаций проверялись существующими Playwright-сценариями, покадровое визуальное сравнение движения не выполнялось.
- Два оставшихся падения `presentation-colors.spec.ts` воспроизводятся на исходной production-сборке: backend не отдаёт thumbnail созданного PPTX. В среде отсутствует LibreOffice/soffice, который использует серверный рендерер. Цвета слайдов и fallback-обложки проходят предшествующие проверки этих сценариев. Backend и API-контракты не менялись.
- Общий запуск E2E с одним backend достигает существующего лимита 15 попыток авторизации за 15 минут. Для полной проверки использовались отдельные запуски файлов; сам лимит не отключался.

Сырые результаты и скриншоты сохранены в `/private/tmp/deckly-optimization`; численные замеры и итоговые статусы сохранены в `../docs/project-audit/frontend-optimization-metrics.json`.
