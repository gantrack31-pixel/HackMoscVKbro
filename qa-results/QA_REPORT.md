# Отчёт о QA-тестировании Deckly.Ai

**Объект:** репозиторий `gantrack31-pixel/HackMoscVKbro`, ветка `fix/preview-editing-cleanup`, коммит `c286bec` («Fix malformed AI edit proposals and enforce response schema»).
**Дата прогона:** 20.10.2026.
**Окружение:** macOS (Apple Silicon, 16 ГБ RAM), Python 3.12, Node 24, Chromium из Playwright, Microsoft PowerPoint для Mac (для рендера и проверки открытия PPTX). LibreOffice не установлен.
**LLM:** live, `qwen38-27b-fp8` через VK AI Space (Inference API). Генерация изображений (FLUX) не подключена.

Продуктовый код не менялся. Все прогоны шли на одноразовых SQLite-базах во временных каталогах, на синтетических данных и тестовых аккаунтах. Рабочий Docker-контейнер и пользовательская база не затрагивались.

> **Важно о версии.** Во время тестирования история ветки была переписана: коммиты `2c753b7` и `7778e8c` (карточки тезисов, 67 иконок, правило визуального промпта, prod-деплой) из ветки исчезли. Весь отчёт относится к `c286bec`. Результаты автотестов, полученные до обновления, отброшены и перезапущены.

## 1. Итог в одном абзаце

Детерминированная часть Deckly.Ai (разбор шаблонов, вёрстка, таблицы, нативные диаграммы, 9 типов схем, аудит, экспорт PPTX/PDF/HTML, импорт материалов, безопасность доступа, отмена и повтор заданий) работает надёжно: **0 повреждённых PPTX из 70+ проверенных файлов**, все числа в нативных диаграммах совпадают с исходными, чужие проекты недоступны. Слабое звено — генерация через LLM. **Презентации на 15–20 слайдов нестабильны:** шлюз провайдера обрывает непотоковые запросы ровно на ~51 с, и D1 (20 слайдов) не удалось получить ни в одной из 3 попыток. Модель почти не использует фотографии из шаблонов, слабо пользуется диаграммами при наличии числовых данных и заполняет большой объём повторами. В схемах и карточках встречается видимое переполнение текста.

**Готовность:** для 5–12 слайдов на тему без данных — пригодно для реального использования с ручной доработкой. Для аналитических и больших (15–20 слайдов) презентаций — **не готово** из-за обрывов провайдера (P1) и дефекта многосерийной аналитики (P1).

## 2. Как устроена генерация (подтверждено кодом и прогонами)

1. **Структура (outline).** `POST /api/outline` → `llm.make_outline`: один запрос к модели со схемой `DeckContent`, бриф (`narrative.brief_from_request`), контекст шаблона (`template_context.model_template`), библиотека иконок и каталог материалов. Ответ проходит строгие проверки: точное число слайдов, числа только из источника (`validate_narrative_slide`), ячейки таблиц и данные графиков из источника (`validate_visual`), иконки и ресурсы только из каталога. При отказе делается **один** повтор: частичный (`SlideRepair`, только отклонённые слайды) или полный (если не совпало число слайдов).
2. **Тип слайда** выбирает модель (text, table, chart, steps, diagram, icons, image, title). Аналитические слайды (`analysis`) создаёт только детерминированный модуль `/api/analysis`, не LLM.
3. **Сборка.** `POST /api/generate` → фоновое задание (`workflow.run_operation`, бюджет 300 с вместе с очередью, 2 параллельных слота) → `llm.create_design_variants`: **три параллельных запроса** `DesignPlan` (варианты A — классический, B — акцентный, C — минималистичный). Модель выбирает только композицию, плотность и стиль схемы, геометрию считает Python (`layout.build_scene`). Затем аудит трёх вариантов.
4. **Шаблон.** `templates.analyze_template` извлекает палитру, шрифты, макеты, фон и изображения из PPTX. Экспорт PPTX строится на исходных мастерах шаблона.
5. **Экспорт.** PPTX (python-pptx): текстовые блоки, нативные таблицы и диаграммы со встроенными книгами Excel, фигуры и соединители для схем. PDF (reportlab) и HTML (SVG) используют ту же геометрию сцены и встраивают Manrope.
6. **Редактор и ассистент.** Ручные правки — `PUT /api/projects/{id}` с проверкой версии. AI-правки — предложение (`proposal`) с явным принятием или отклонением. Есть история отмены и повтора, а также пересборка оформления с пожеланием, без изменения фактов.
7. **Ошибки.** Таймауты, 429/5xx, повреждённый JSON, обрывы — понятные сообщения, частичный результат не публикуется. Один автоповтор при обрыве соединения.

## 4. Ответы на вопросы финального вывода

**Насколько готов к реальному использованию?** Для коротких (5–12 слайдов) презентаций на тему — да, с оговорками: нужна ручная правка переполненных схем, однообразных текстовых слайдов и выбора иконок. Для аналитики и 15–20 слайдов — нет, до исправления BUG-01 и BUG-02.

**Что действительно работает.** Экспорт PPTX/PDF/HTML (нативные и редактируемые объекты), аудит, все 9 типов схем, таблицы, нативные диаграммы, шаблоны любых пропорций, тёмные и фото-фоны шаблонов, импорт 11 форматов материалов, изоляция пользователей, отмена и повтор заданий, AI-правки с предложениями, пересборка оформления без изменения фактов, устойчивость к prompt injection в документах.

**Что работает частично.**
- Использование фотографий из шаблонов: движок умеет, модель не выбирает.
- Аналитический модуль: grouped не генерируется, заголовки «сырые».
- Импорт брендбука: не работает на macOS.
- Генерация на 15–20 слайдов.
- Распознавание единиц и годов в CSV.

**Какой уровень сложности стабилен.** Простой и средний (5–12 слайдов): 4 из 5 попыток успешны, единственный отказ — B2 из-за проверки чисел. Сложный — 2 из 3 попыток. Стресс (20 слайдов) — 0 из 3.

**Когда ухудшается качество.** Начиная примерно с 15 слайдов. Модель добивает объём повторами (C1: региональные данные трижды, сводная таблица дважды), доля чисто текстовых слайдов растёт до 61% (C2: 11 из 18), а время ответа подходит к 51-секундному обрыву шлюза.

**Способна ли LLM сама выбирать графику?** Частично. Для перечислений она выбирает иконки, для процессов и связей — схемы, но:
- для чисел из CSV ставит таблицы вместо графиков (C1: 0 графиков);
- фото шаблона не выбирает ни разу;
- иногда ошибается со структурой (нейросеть как иерархия).

**Сохраняется ли оформление шаблона.** Хорошо: фон (включая фото-фон «Экология города» и декор «Приюта для животных»), палитра, цвет заголовков, пропорции 16:9, 4:3 и 3:4. Слабо: шрифты — Manrope не встраивается в PPTX, и PowerPoint подставляет замену.

**Корректность таблиц, диаграмм и схем.** Данные — точные. Геометрия — встречается переполнение подписей в узлах схем и карточках иконок, видимое и в PDF, и в PowerPoint, а также диагональные соединители при переносе процесса на вторую строку.

**Редактируемость PowerPoint.** Да: текст в текстовых блоках, таблицы нативные, диаграммы нативные со встроенными данными, схемы из фигур и соединителей. Ни один слайд не является растром.

**Стабильность экспорта и повторного редактирования.** Экспорт — 100% (0,01–0,16 с на файл). Повторное оформление 4 из 4 сохранило тексты и данные. Отмена и повтор, конфликт версий, принятие и отклонение AI-предложений работают.

**Самые частые ошибки.**
1. Обрыв LLM-запроса на 51 с.
2. Переполнение текста в схемах и карточках (аудит находит 1–11 ошибок `overflow` на колоду).
3. Модель игнорирует фото шаблона.
4. Отказ структуры из-за «чисел не из источника» (модель пишет сроки или количества, которых нет в теме).
5. Однообразные текстовые слайды с пустой половиной.

**3–5 изменений с наибольшим эффектом** — подробно в `RECOMMENDATIONS.md`:
1. Потоковый режим (`stream=true`) в `llm.complete_json`.
2. Убрать хвостовой пробел в заголовках grouped-аналитики и нормализовать сравнение.
3. Подгонка текста узлов схем (`visuals.diagram_nodes`, `pictogram_nodes`) по реальной высоте и встраивание или замена шрифта в PPTX.
4. Явные правила и примеры в промпте: фото шаблона для титула и разделов, график для каждой числовой серии, запрет повторов.
5. Починить тестовую обвязку, чтобы тесты live-ветки реально выполнялись.

## 5. Ограничения проверки

- PowerPoint использовался только для открытия, рендера в PDF и контроля отсутствия диалога восстановления. Прямой UI PowerPoint не проверялся. LibreOffice не установлен.
- FLUX, Яндекс ID, Яндекс.Диск и SMTP не настроены — **BLOCKED** (обработка их недоступности проверена E2E `disk.spec`).
- Ручная проверка UI выполнялась выборочно (сценарий ложного конфликта редактора). Интерфейсные сценарии в остальном покрыты 51 пройденным E2E.
- Число live-прогонов ограничено бюджетом (около 130 вызовов модели). Частоты отказов — оценки на малой выборке.
