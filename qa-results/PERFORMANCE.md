**Стенд:** MacBook (10 ядер, 16 ГБ), backend uvicorn в одном процессе, SQLite, live-провайдер VK AI Space (`qwen38-27b-fp8`). Сеть — обычный интернет. Время LLM определяется провайдером и сильно варьируется.

## 2. Лимит 300 с (сборка с очередью)

- Все успешные сборки уложились: максимум — C1, 96 с.
- Три параллельные сборки (8 слайдов): 32,6 / 61,9 / 32,6 с. Слотов 2, третья ждёт; все ≤ 300 с.
- Структура под бизнес-лимит 300 с не подпадает (по документации), но фактически упирается в **обрыв шлюза провайдера на 51 с** (BUG-01). Это главный ограничитель производительности, а не код Deckly.

## 3. Отказоустойчивость (Mock)

| Ситуация | Время до ответа | Результат |
|---|---|---|
| Зависание провайдера | 20 с (тестовый `LLM_TIMEOUT_SECONDS`) | 502, понятное сообщение |
| Обрыв, затем успех | 1 с | Автоповтор, структура получена |
| 429 / 5xx | <0,1 с | 502, без повтора |
| Отмена задания | мгновенно | `cancelled`, проект не публикуется |

## 4. Эксперимент: поток против обычного запроса (Live)

Один и тот же запрос с длинным ответом (около 7000 токенов):
- без `stream`: **RemoteProtocolError через 51,2 с**;
- с `stream=true`: **успешно за 168,7 с**, 3726 фрагментов, 26 тыс. символов.

Скорость вывода модели — около 85–110 токенов/с на одном запросе. Три параллельных запроса не замедляют друг друга (проверено ранее: 7,6 с против 13,3 с одиночного).

## 5. Интерфейс

Загрузка интерфейса покрыта E2E `loading` и `optimization` (PASS). Отдельный профилировщик `scripts/profile-browser.mjs` в этом прогоне не запускался (NOT_RUN): он меряет экран входа, на который проверяемые изменения не влияют.
