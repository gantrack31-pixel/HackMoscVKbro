# Исправления предварительного просмотра и AI-редактирования

Работа выполнена в `fix/preview-editing-cleanup`, база — `6b032ef92d14a6b81ceabc4749d07f511565c5e4` (`Add mascot to outline generation and harden large inputs`). Ветка `main` не изменялась, PR не создавался.

Это целевая стабилизация, а не переписывание проекта. Сохранены генерация, три варианта дизайна, ручной редактор, аналитика, шаблоны, история, облачные интеграции и экспорт. ## Что было слабым и что изменено

| Проблема | Решение |
| --- | --- |
| Предложение AI было трудно оценить до применения: текстовый diff не показывает геометрию. | Изолированный визуальный предпросмотр «текущий черновик / после принятия». Два preview-запроса выполняются параллельно и ничего не сохраняют. Применение доступно только после успешного построения. |
| Отклонённые предложения попадали в контекст как уже сделанная работа. | История пополняется только после успешного применения. Старый неоднозначный локальный формат истории не переносится. |
| Пользователь мог продолжить редактирование, пока прежнее предложение оставалось активным. | UI блокирует применение при изменении черновика/версии и истечении срока. Серверная проверка версии, fingerprint, владельца и атомарное применение сохранены. |
| Защита чисел мешала исправлять ошибочные факты и не ловила простые перестановки значений между показателями. | По умолчанию числа защищены. Для замены есть явное разрешение и контракт `before/after/evidence`: точная цитата должна быть найдена в полном источнике. Добавлена проверка простых записей «показатель: число». |

| Обычная AI-правка могла принести новую ошибку вёрстки, а repair/no-op создавал впечатление исправления. | И edit, и repair отклоняют новые error-замечания по изменяемым слайдам во всех A/B/C. Пустой результат не считается исправлением; автопочинка проверяет исчезновение замечания. Непочиненный overflow не объявляется автоматически исправленным. |

| Vision видел картинки шаблона вместо текущего состояния слайда. | Для помощника передаются PNG текущих сцен (до четырёх), а не картинки-примеры из шаблона. |
| Проверка аналитики только на одном этапе допускала обход через ручное сохранение/экспорт. | Общий серверный guard для обновления, AI-черновика, применения и экспорта, включая Яндекс.Диск. Новая аналитика должна соответствовать текущему расчёту владельца; собственный hash клиента не даёт права изменять данные. |

## Что относится к последнему базовому коммиту

Коммит `6b032ef` уже добавил увеличение лимита вывода outline при повторе, распознавание обрезанного ответа, тесты больших входов/PPTX и UI-индикацию. Эти улучшения сохранены, они не являются результатом данной ветки.

Оставшийся риск: 50 000 **символов входа** не означают, что требуемый JSON поместится в выходной бюджет или контекст выбранного провайдера. Повтор с большим бюджетом увеличивает возможную задержку и стоимость; маскот этого не решает. Последний коммит не закрывал контракт исправления фактов, визуальное сравнение предложений и избыточный контекст помощника — их исправляет эта ветка. Нельзя приписывать все старые ошибки именно последнему коммиту.

## Как работает модель по этапам

Конкретный checkpoint не зашит в алгоритм: он берётся из окружения. Провайдер задаётся через `LLM_BASE_URL`, `LLM_MODEL` и `LLM_API_KEY`. Значения по умолчанию в коде — endpoint VK AI Space и `qwen38-27b-fp8`; для OpenRouter явно укажите его URL и идентификатор модели. Существование и доступность этих идентификаторов у провайдера здесь не проверялись. Поставщик должен поддерживать OpenAI-compatible `/chat/completions`; `LLM_JSON_MODE=true` запрашивает JSON object, а не гарантированную constrained generation. Pydantic и предметные проверки выполняются после ответа.

| Этап | Вход/роль модели | Ограничения и результат |
| --- | --- | --- |
| Материалы и шаблон | Разбор файлов и извлечение контекста выполняет сервер, не LLM. | В модель передаётся ограниченное описание шаблона: до 16 layouts, 6 примеров по 12 объектов, каталоги ресурсов до 80 элементов. Тексты примеров не считаются фактами новой презентации. |
| Структура / outline | Цель, аудитория, исходный prompt, шаблон, каталог. LLM возвращает `DeckContent`. | Prompt до 50 000 символов, запрошено 3–20 слайдов. До 3 попыток. Базовый выход 12 000 токенов, повторные бюджеты по умолчанию 24 000/48 000. Проверяются точное число слайдов, схема, числа, визуальные элементы и допустимые ID. |
| Аналитические слайды | Значения, расчёты и планы строятся детерминированно по набору данных владельца. | LLM не получает права переписывать вычисления. Общий deck допускает до 200 слайдов; это не то же самое, что лимит 20 слайдов narrative outline. |
| Дизайн A/B/C | Один запрос планирует сразу три варианта narrative-слайдов. Вход включает краткий body (до 400 символов), bullets, размеры таблиц, тип графика. | Выход 16 000 токенов, до 2 попыток. Каждый вариант обязан покрывать все narrative-индексы, планы должны различаться. Аналитические слайды оформляются детерминированно. Модель выбирает ограниченные дизайн-параметры, а не произвольный PowerPoint XML. |
| Изображения | Отдельный сервис `FLUX.1-schnell`, если настроен. | Запрос: 4 шага, 512 px; concurrency по умолчанию 2 (1–8). Ответ до 1 MiB, размер изображения до 1024 px на сторону. Это не текстовая LLM. |
| Preview и геометрический аудит | Детерминированный layout/render/audit. | Здесь LLM не вызывается. Сцена принадлежит серверу; overflow и остальные геометрические замечания не должны скрываться флагом `fixed`. |
| Смысловой аудит | LLM получает материал по chunks, презентацию и привязки цитат. | Выход 4 000 токенов; максимум 12 замечаний. Работает только в live при включённом context audit. Ошибка модели означает «проверка недоступна», а не «ошибок нет». Цитаты проверяются сервером; отсутствие подтверждения обозначается явно. |
| Исправление перед скачиванием | Текущий черновик, выбранный слайд или весь deck, инструкция, закрепления, принятая история, материал и геометрия. | Инструкция до 3 000, дополнительный материал до 15 000, brief до 4 000 символов; история до 10 реплик, 30 фактов/60 блокировок, 30 переданных замечаний. Основной источник ограничен релевантной выборкой до 16 000 символов; полный источник остаётся для серверной валидации. Выход 8 000 токенов, до 2 попыток на проход; repair — до 2 проходов, то есть максимум 4 вызова при исправимых ответах. Vision опционален, максимум 4 текущие сцены. Результат — предложение, не сохранение. |
| Принятие / отмена | LLM не вызывается. | Предложение живёт 30 минут. Сервер проверяет исходник, черновик, вариант, версию и владельца; публикует атомарно. Undo восстанавливает и содержание, и дополнительные источники. |
| PPTX / PDF / HTML / Диск | Детерминированный экспорт, LLM не вызывается. | Общая сцена и эффективный шрифт уменьшают расхождения; PowerPoint может иначе отрисовать native chart/master. Проверка аналитики повторяется до экспорта. |

Общие настройки: temperature 0.3, сетевой read/write inactivity timeout 180 s, connect/pool 15 s. Это не полный deadline операции. Полная генерация/регенерация ограничены 300 s с учётом очереди; outline, помощник, image и смысловой аудит не имеют общего business deadline. Stop закрывает локальный запрос, но не гарантирует прекращение вычисления/биллинга у удалённого провайдера. В логах LLM — длительность, finish reason и usage, без материалов и секретов.

## Что остаётся ограничением

1. Реальный live-провайдер, его квоты, время ответа и качество исправления произвольных русских презентаций без ключа/сервера не проверены. Нужен отдельный live smoke-test на ваших типичных входах.
2. Проверка чисел, цитат и простых пар «показатель: значение» не является универсальным доказательством смысловой достоверности. Текст без чисел может быть ошибочным; точная цитата сама по себе не доказывает правильность интерпретации. Для ответственного использования нужен человеческий просмотр.
3. Выборка источника лексическая, не embedding/RAG: нужный фрагмент может не попасть в 16 000 символов. Можно явно приложить релевантный материал или сузить правку до слайда. Семантическое качество такого retrieval не измерено.
4. При правке всего deck полный контекст всех разрешённых слайдов остаётся: общего точного token-budget по контекстному окну провайдера пока нет. Оптимизация максимальна для slide-scoped edits.
5. Vision PNG — снимок серверной сцены, не screenshot PowerPoint. Растризация не гарантирует совпадения тонких деталей всех chart/master/SmartArt. При правке всего deck видны только первые четыре сцены.
6. Manrope — намеренный fallback; точное сохранение пользовательских шрифтов требует отдельного безопасного font pipeline. Не обещается пиксельная идентичность браузера и Office.
7. Глобальное удаление файлов/ассетов без доказанной неиспользуемости не выполнялось: это могло бы сломать шаблоны и скрытые сценарии. Сокращение контекста и повторной работы важнее косметического уменьшения числа файлов.
