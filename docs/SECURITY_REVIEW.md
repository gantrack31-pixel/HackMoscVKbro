# Проверка безопасности — 26 сентября 2026

Проверены обработка сессий, CSRF, доступ к презентациям/экспорту/заданиям, ответы API, загрузка PPTX, HTML-экспорт и зависимости. Существующие проверки подтверждают изоляцию владельцев, scrypt-хеширование паролей, хранение хешей сессионных токенов и экранирование содержимого слайдов. `.env`, базы данных и личные загрузки не отслеживаются Git.

Исправлено:

- Ошибки валидации больше не возвращают введённые пароли и материалы.
- Добавлена CSP: скрипты и соединения только с собственным origin; запрещены плагины, подмена base URL и встраивание страницы. Для стилей сохранён inline, необходимый динамическим слайдам. Документация API отключена в production; локальный Swagger оставлен доступным.
- Добавлены Permissions-Policy и HSTS в production. Камера, микрофон и геолокация не требуются приложению; fullscreen разрешён для своего origin.
- Внешний LLM допускается только по HTTPS; локальный HTTP на loopback сохранён. URL с секретами в query/fragment или userinfo отклоняются до отправки запроса.
- Фоновые задания не записывают содержимое исключений и цепочки ответов модели в журнал; остаются ID задания и класс ошибки.
- Обновлены уязвимые серверные зависимости и Vite/esbuild, включая исправления Windows dev-сервера.

Результаты после объединения с обновлениями GitHub (восстановление заданий, проверка PPTX): 74 backend-теста прошли, 1 проверка внешнего облака пропущена; 7 frontend-тестов прошли, production-сборка успешна. `pip-audit` установленного Python-окружения и полный `pnpm audit` после обновления: известных уязвимостей не найдено. Это результат базы advisories на момент проверки, а не гарантия отсутствия всех уязвимостей. Добавленный в GitHub набор Playwright E2E в этой сессии не запускался; браузерные проверки выполнены отдельно.

## Границы

Это проверка кода и автоматических сценариев, не внешний пентест инфраструктуры. SQLite, исходные PPTX и материалы хранятся на диске без шифрования уровня приложения. Полный захват серверной ОС даст доступ к этим файлам и серверным ключам. Для размещения нужны HTTPS, минимальные права службы, шифрование диска и резервных копий с отдельным управлением ключами, ограничения запросов на reverse proxy и своевременные обновления. Настройки описаны в VALIDATION.md. Материалы отправляются выбранному владельцем сервера провайдеру только при использовании функций LLM.

В браузере на отдельном локальном тестовом аккаунте проверены вход, главная, каталог, презентации, избранное, демонстрация, поддержка, профиль, создание, редактор, проверка слайдов и завершение. Проверены светлая и тёмная темы; исправлен контраст заголовка подсказки. На ширине 430 px каталог и форма создания не вызывают горизонтального переполнения. Консоль браузера не показала ошибок при обходе. Добавлены шрифтовые акценты обложек, переносы длинных заголовков и мягкие hover-переходы с поддержкой reduced-motion. Реальный внешний LLM и облачное хранилище в этой локальной проверке не использовались.
