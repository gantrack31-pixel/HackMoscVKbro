# Подключение Яндекс ID

В приложении реализован реальный OAuth Authorization Code + PKCE (S256). Без зарегистрированного приложения Яндекса вход недоступен. Заглушки авторизации нет.

1. Откройте [Яндекс OAuth](https://oauth.yandex.ru/) под аккаунтом владельца проекта и зарегистрируйте веб-приложение Deckly.Ai.
2. Укажите адрес сайта: `http://127.0.0.1:8000`.
3. В Redirect URI укажите **точно**: `http://127.0.0.1:8000/api/auth/yandex/callback`.
4. Выберите права `login:info` (имя и идентификатор) и `login:email` (электронная почта).
5. Скопируйте публичный **Client ID** в `backend/.env`: `YANDEX_CLIENT_ID=ваш_client_id`. Если файла ещё нет, скопируйте `.env.example`. Существующий `.env` не перезаписывайте.
6. Перезапустите сервер. На экране входа выберите «Войти с Яндекс ID».

## Страница авторизации и поля на скриншоте

Кнопка входа размещена на отдельной публичной странице `/auth/yandex`. Она доступна без сессии; обновление страницы поддерживается сервером. Переход с неё использует существующий `/api/auth/yandex/start` и проверку state + PKCE. Пароль Яндекса сайт не запрашивает.

Для локальной проверки:
- Страница кнопки: `http://127.0.0.1:8000/auth/yandex`.
- **Redirect URI:** `http://127.0.0.1:8000/api/auth/yandex/callback`.
- **Suggest Hostname:** хост страницы с кнопкой, `http://127.0.0.1:8000` (без `/auth/yandex`). Это поле относится к виджету мгновенной авторизации; текущая кнопка использует серверный OAuth, а не виджет.

Для публикации укажите свой настоящий HTTPS-домен вместо локального адреса во всех трёх адресах. `https://oauth.yandex.ru/verification_code` не является callback этого приложения. Ключи остаются только в `backend/.env`.

Без Client ID страница показывает недоступность входа и предлагает вход по почте. Проверка доступности не означает, что настройки приложения уже подтверждены Яндексом.

Секретный ключ не обязателен: Яндекс разрешает обмен кода без Client Secret при PKCE. Если ключ уже настроен, сервер продолжит его использовать. Секреты не помещайте в React и не публикуйте в репозитории.

При переходе на публичный домен замените адреса сайта и callback в настройках Яндекса и в `.env` (`PUBLIC_BASE_URL`, `YANDEX_REDIRECT_URI`), включите HTTPS и `COOKIE_SECURE=true`.

## Существующий аккаунт

Войдите по почте → меню профиля → «Профиль и настройки» → «Вход и безопасность» → «Подключить Яндекс ID». Презентации останутся в том же аккаунте. Совпадение почты без явной привязки не объединяет аккаунты. Уже занятый Яндекс ID связать со вторым аккаунтом нельзя.

## Проверка

`GET /api/health` сообщает `yandex_enabled: true`, когда указан Client ID. Это признак конфигурации, а не подтверждение успешного входа у провайдера. Настоящий вход нужно пройти в браузере после регистрации приложения. Автотесты проверяют обмен кода, PKCE, повторный вход, одноразовый state, привязку к текущей сессии и изоляцию аккаунтов с подменёнными ответами Яндекса.

Документация: [регистрация приложения](https://yandex.ru/dev/id/doc/ru/register-client), [код авторизации и PKCE](https://yandex.ru/dev/id/doc/ru/codes/code-url).
