# Ветка `fix/auth-rate-limit-behind-proxy`

Исправляет общую блокировку входа на сайте, развёрнутом за обратным прокси (Railway).

## Проблема

Лимит попыток входа (15 за 15 минут) считался по `request.client.host`. На Railway все запросы приходят на сервер с адреса прокси, а uvicorn не доверяет его заголовкам. В итоге у всех посетителей оказывался один и тот же IP, а значит, один общий лимит.

Кроме того, в лимит шли и **успешные** входы. После 15 входов или регистраций от любых пользователей сервер на 15 минут начинал отвечать всем `429 Слишком много попыток`. Та же ошибка была в лимите формы поддержки.

## Что изменено

| Файл | Изменение |
| :--- | :--- |
| `backend/app/config.py` | Новая настройка `TRUSTED_PROXY_HOPS` (по умолчанию `0`, допустимо 0–5) с проверкой при старте. |
| `backend/app/auth.py` | `client_ip()` берёт реальный IP посетителя из `X-Forwarded-For`. `rate_limit()` умеет только проверять лимит, не записывая попытку. Новая `record_auth_failure()`. |
| `backend/app/auth.py` → `/api/auth/login` | В лимит записываются только неверные пароли. |
| `backend/app/main.py` | Лимит формы поддержки тоже использует `client_ip()`. |
| `backend/tests/test_auth_rate_limit.py` | Новые тесты. |
| `README.md`, `.env.docker.example` | Описание настройки, `TRUSTED_PROXY_HOPS=1` в инструкции для Railway. |

Регистрация, подтверждение почты и сброс пароля по-прежнему расходуют попытку при каждом запросе.

## Как работает `TRUSTED_PROXY_HOPS`

Каждый прокси дописывает в **конец** `X-Forwarded-For` адрес, с которого к нему пришёл запрос. Сервер берёт запись под номером `N` с конца, где `N` — число наших прокси. Записи левее неё прислал сам клиент, их можно подделать, поэтому они игнорируются.

| Окружение | Значение |
| :--- | :--- |
| Локально, Docker Compose на `127.0.0.1` | `0` (по умолчанию) |
| Railway | `1` |
| Свой nginx + Cloudflare | `2` |

Если указать значение больше реального числа прокси, клиент сможет подставить свой IP и обойти лимит. Если указать меньше, вернётся общий лимит на всех.

## Как включить на Railway

1. Смержить ветку и задеплоить.
2. В **Variables** сервиса добавить `TRUSTED_PROXY_HOPS=1`.
3. Проверить: 16 раз ввести неверный пароль с одного устройства. На 16-й раз должен прийти `429`, а вход с другой сети при этом продолжает работать.
