# Gemma, предпросмотр и интеграции

## Gemma: структурированные визуализации

В demo внешние AI-запросы не выполняются. Для Gemma-3-27B-IT через OpenRouter:

```dotenv
LLM_MODE=live
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
OPENROUTER_MODEL=google/gemma-3-27b-it
OPENROUTER_API_KEY=YOUR_SERVER_KEY
LLM_JSON_MODE=true
```

Собственный сервер: задайте `LLM_BASE_URL=http://127.0.0.1:8001/v1`, `LLM_MODEL` с идентификатором развёрнутой модели и `LLM_API_KEY`. Эти три параметра выбираются одним набором, без fallback ключа OpenRouter. Для внешнего сервера обязателен HTTPS. Пустой ключ допустим только у локального endpoint. Обычный `LLM_MODEL` без `LLM_BASE_URL` игнорируется во избежание случайного использования старых настроек.

Gemma IT принимает инструкции внутри первой user-реплики: [официальное описание формата](https://ai.google.dev/gemma/docs/core/prompt-structure). Если провайдер не поддерживает `response_format`, установите `LLM_JSON_MODE=false`: извлечение JSON, Pydantic-валидация и одна корректирующая попытка сохраняются. Лишние поля, неоднозначный JSON, неизвестные иконки и некорректная геометрия не принимаются. В схему модели не отправляется legacy SmartArt-геометрия: модель выбирает семантику, координаты рассчитывает Python.

| Объект | Ограничение новых AI-данных | PPTX |
| --- | --- | --- |
| Таблица | До 7 строк с заголовком × 5 колонок, ячейка до 160 символов, точные данные из материала | Нативная таблица |
| График | Один ряд, 1–6 категорий, подпись до 80 символов, обязательная единица; bar / column / line | Нативный chart с данными |
| Схема | До 6 узлов; process, cycle, hierarchy, matrix и другие разрешённые типы | Фигуры и соединители, не bitmap и не OOXML SmartArt |
| Иконки | AI выбирает из серверного каталога, до 6 тезисов | Отдельные PNG-объекты: можно перемещать/масштабировать; не редактировать контуры |
| Фон и типографика | Цветовые роли шаблона; heading/body, ограниченные масштабы, normal/bold | Настоящий фон и текстовые свойства |

Исходные вручную введённые/старые таблицы большего размера остаются читаемыми. Нельзя подменять график с отсутствующими данными случайными числами: валидатор требует точную категорию, значение и единицу в записи источника либо в структурированной CSV/TSV/Markdown-таблице с явной единицей в заголовке. Невалидные ответы повторяются один раз, затем возвращается ошибка без сохранения изменений. Вычисленные доли, прогнозы и переводы единиц без явных исходных значений намеренно не поддерживаются.

Пример материала:

```text
Команда;Доля %
Команда А;10
Команда Б;20
```

Запросы помощнику: «Представь доли столбчатой диаграммой», «Сделай таблицу из этих данных», «Преобразуй этапы в схему», «Верни данные графика в текст». Помощник видит текущий черновик и дополнительный материал; изменения сохраняются атомарно с отменой. Design-only генерация использует отдельную схему, не содержащую поля для переписывания текста.

Проверки чисел — консервативная защита, не полная проверка достоверности смысла. Сложные источники могут потребовать более явной таблицы или ручной правки. Автономный выбор формата зависит от качества ответа подключённой модели; тесты с mock-провайдером проверяют контракт, не качество реальной Gemma.

## Предпросмотр исходного PPTX

Linux: `apt-get install libreoffice-impress poppler-utils fonts-dejavu-core fonts-liberation`. Для точного шрифта установите разрешённые лицензией гарнитуры шаблона. В Windows нужны LibreOffice (`soffice` в PATH или стандартном Program Files) и `pdftoppm` в PATH.

Сервер делает копию PPTX, удаляет внешние relationships только в конвертируемой копии, запрещает макросы в отдельном профиле LibreOffice, преобразует первый слайд в PDF и PNG. Лимиты конвертации — 45 с и 20 с. Исходный файл не переписывается. Используются защитные проверки ZIP и размеров изображения. Кэш PNG: SHA-256 исходника + версия нормализации + версия renderer; ошибки кратко кэшируются на 60 с. Доступ к пользовательским миниатюрам проверяется по владельцу, как к исходнику.

Без конвертера используется встроенная миниатюра документа, если она есть. Она могла устареть внутри самого файла: для достоверного актуального первого слайда установите LibreOffice. Если изображения нет или конвертация не удалась, UI честно сообщает об этом, не рисуя вымышленную обложку. Редактор и аудит по-прежнему показывают схему размещения, не полный рендер мастера PowerPoint. Headless-конвертер не является полноценной песочницей: production запускайте непривилегированно, с лимитами контейнера и ограничением исходящего трафика.

## Яндекс.Диск

1. В приложении Яндекс OAuth разрешите `login:info`, `login:email`, `cloud_api:disk.app_folder`.
2. Задайте `YANDEX_CLIENT_ID`, `YANDEX_REDIRECT_URI`, при необходимости `YANDEX_CLIENT_SECRET`. Callback: `/api/auth/yandex/callback`, точно как в кабинете; production — HTTPS.
3. Создайте ключ: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`. Сохраните результат только в серверном `YANDEX_DISK_TOKEN_KEY`. Не публикуйте его в Git и храните резервную копию отдельно от SQLite.
4. Перезапустите сервер. На финальном экране подключите Диск и выдайте разрешение. Обычный вход через Яндекс сам по себе не запрашивает права Диска.

Используется [REST API Яндекс.Диска](https://yandex.com/dev/disk/rest/): папка `app:/Deckly`, запрос upload URL, отправка настоящих байтов PPTX, затем проверка размера и MD5. Уникальное имя + `overwrite=false` не затрагивают старые файлы. Максимум 75 МБ; список показывает последние 100 PPTX. В UI подтверждение появляется только после успешной проверки провайдера. Токен зашифрован Fernet в SQLite, не возвращается в JSON и не передаётся на upload host. Загрузка разрешена только по HTTPS на домены загрузки Диска.

Истёкшее/отозванное разрешение, отсутствие прав, нехватка места, rate limit, отказ API и сетевые ошибки дают понятный ответ, не затрагивая локальный проект. Повторное подключение существующего Яндекс-аккаунта поддержано; другой аккаунт нельзя незаметно подставить к уже привязанному профилю. Смена ключа шифрования требует переподключения. Автоматического refresh flow нет — требуется повторный OAuth.

В Диск экспортируется выбранный PPTX, а не SQLite, история undo или вся библиотека шаблонов. Старые PostgreSQL backup API сохранены, но UI больше не обозначает их как новое облачное сохранение. Резервное копирование сервера настраивается отдельно.

## SMTP и поддержка

```dotenv
SMTP_HOST=smtp.example.org
SMTP_PORT=587
SMTP_SECURITY=starttls
SMTP_USERNAME=sender@example.org
SMTP_PASSWORD=YOUR_APP_PASSWORD
EMAIL_FROM=sender@example.org
SUPPORT_TO=help@example.org
SUPPORT_RATE_LIMIT=5
```

`auto`: STARTTLS на 587, SSL на остальных портах. `ssl`: TLS сразу, обычно 465. Отключение TLS не поддерживается; сертификаты проверяются. Общий транспорт используется для подтверждения почты, сброса пароля и поддержки. Пароль приложения хранится только на сервере. From должен быть разрешён SMTP-провайдером; Reply-To поддержки — адрес пользователя. Пустой SUPPORT_TO использует EMAIL_FROM.

Успех = SMTP принял всех получателей; bounce/spam после приёма требуют проверки у почтового провайдера. Сбой SMTP возвращает 503 без деталей с секретами. Антиспам: квота аккаунта за 15 минут, общая IP-квота в 4 раза больше и отдельный минутный burst-limit. Неуспешная доставка освобождает длинную квоту, но учитывается в burst. Development по умолчанию допускает 30 обращений; production — 5. Лимиты не отключайте на публичном сервере.

## Необязательные изображения

Gemma выбирает содержимое и тип представления; генерация bitmap остаётся отдельным FLUX-сервисом (`IMAGE_BASE_URL`, `IMAGE_API_KEY`). Без него доступны текст, таблицы, графики, схемы и библиотечные иконки. Настройка: [REQUIREMENTS.md](REQUIREMENTS.md). Общие deadline, Stop, HTTP pool, concurrency и метрики: [AI_OPERATIONS.md](AI_OPERATIONS.md).
