# Проверки сборки

Автоматические проверки: TypeScript (`tsc --noEmit`), production-сборка Vite, frontend unit-тесты, Playwright E2E на отдельной временной SQLite и backend pytest на отдельной временной SQLite. Исходные шаблоны при тестировании открываются только для чтения.

Покрыто: регистрация, scrypt-хеш вместо пароля, HttpOnly-сессия, вход/выход, CSRF и Origin; недоступность чужих проектов/заданий/экспорта/изменений; избранное в разных аккаунтах; неверный PPTX; новый шаблон 4:3; сохранение, аудит, выбранное исправление и отмена; LLM JSON/ошибки провайдера; Яндекс PKCE и повторное/чужое state; девять сочетаний исходных шаблонов и композиций с нативными текстом, диаграммой и таблицей; PDF с кириллицей, HTML и отрицательные значения диаграммы.

В браузере проверяются: главная, каталог, форма материалов, структура из 10 слайдов, генерация, выбор варианта, сохранение названия, защита несохранённых изменений, редактор, аудит, скачивание, поддержка, адаптация ширины. Список найденных при проверке проблем исправлен: конфликт CSS-класса WorkSpace, обрезание ввода данных при наборе, подмена некорректного числа нулём, лишние замечания контраста крупного текста, положение прокрутки между этапами.

Внешние сервисы: настоящий LLM-запрос и настоящий OAuth Яндекса не выполнялись, поскольку ключи не предоставлены. Используются тестовые HTTP-ответы. Плагин для Figma подготовлен отдельно и не запускался в пользовательском файле. Проверка девяти PPTX подтверждает их структуру и редактируемые объекты; рендер PowerPoint на этом компьютере не выполнялся.

## Production checklist

- Установите `APP_ENV=production`; укажите `PUBLIC_BASE_URL` с публичным HTTPS-origin, а в `CORS_ORIGINS` — только HTTPS origins, включая origin публичного URL. Wildcard, localhost и loopback-адреса отклоняются при запуске.
- Установите `COOKIE_SECURE=true`. Для `LLM_MODE=live` задайте серверный `LLM_API_KEY`; демонстрационный режим в production требует явного `ALLOW_DEMO_IN_PRODUCTION=true`. Секреты передавайте через защищённое хранилище переменных окружения, не коммитьте `.env` и не помещайте ключи в логи.
- При включённом Яндекс OAuth используйте `YANDEX_REDIRECT_URI=https://<тот-же-хост>/api/auth/yandex/callback` и зарегистрируйте точно такой же адрес в кабинете OAuth. Client Secret не обязателен при использовании PKCE.
- Перед релизом выполните pytest и production-сборку, разверните сначала staging и проверьте регистрацию/вход, CSRF, OAuth (если включён), загрузки и экспорт через HTTPS. Обновляйте зависимости из lock/requirements-файлов и применяйте обновления безопасности.
- Ограничьте доступ к серверу и хранилищу; включите TLS на reverse proxy, ограничение размера/частоты запросов и мониторинг доступности. Не записывайте пароли, cookie, CSRF-токены, OAuth-коды и содержимое презентаций в журналы; храните журналы с минимально необходимым сроком и доступом.
- Настройте регулярные зашифрованные резервные копии базы данных и загруженных файлов вне сервера. Контролируйте успешность копирования и периодически проверяйте восстановление на отдельной среде.
- При инциденте ограничьте доступ/отключите затронутый сервис, сохраните необходимые журналы без распространения секретов, смените скомпрометированные ключи, восстановите данные из проверенной копии и зафиксируйте первопричину перед повторным запуском.

Production-проверка конфигурации выполняется при входе в FastAPI lifespan до создания каталогов и инициализации БД. Локальный `APP_ENV=development` сохраняет HTTP, demo и текущие адреса разработки.

Эти проверки не означают обещания полного отсутствия ошибок на любых данных. Для сдачи повторите сценарий с материалом организаторов и подключёнными сервисами.
