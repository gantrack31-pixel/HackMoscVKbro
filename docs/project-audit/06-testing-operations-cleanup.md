# Тестирование, эксплуатация и очистка

## Результаты локальной проверки

- Backend: 133 passed, 1 skipped. Использовано локальное окружение `backend/.venv`; Python в этом окружении — 3.14. Выведено 66 deprecation warnings из используемых FastAPI/Starlette/AnyIO API.
- Frontend unit: 10 passed.
- Frontend production build: `tsc --noEmit` и Vite build завершились успешно.
- Playwright E2E, внешний Cloud PostgreSQL, live OAuth, реальная генерация LLM/изображений и визуальный рендер PowerPoint в этой сессии не запускались.
- README задаёт Python 3.11–3.13 и Node 22.12+; успешный pytest на 3.14 не отменяет предупреждение проекта не использовать этот runtime.

## Тестирование и эксплуатация

### OPS-1. Поддерживаемые версии должны быть проверяемы воспроизводимой CI-матрицей — P1

**Основание:** заявленный диапазон Python отличается от версии локальной среды. Нет оснований заключать, что 3.14 поддержан или сломан: текущий suite прошёл, но dependency warnings сигнализируют о будущем API breakage.

**Действия:** проверить GitHub Actions/CI конфигурацию (на момент поверхностной инвентаризации workflow не был подтверждён), запускать pytest на поддерживаемых 3.11/3.12/3.13 и frontend test/build. Для 3.14 добавить informational job до официального расширения поддержки.

**Готово, когда:** PR показывает воспроизводимую матрицу, а версии в README, Dockerfile, CI и requirements согласованы.

### OPS-2. Полный браузерный набор не является результатом текущего прогона — P1

Запустить `pnpm run test:e2e` из `frontend/` на чистой установке Chromium и записать фактический результат. Если E2E нестабилен, изолировать источник по trace; не заменять его утверждением, что unit suite прошёл.

### OPS-3. Резервные копии, мониторинг и ограничение запросов — P0 для публичного запуска

Следовать уже имеющемуся `docs/VALIDATION.md`: зашифрованная копия БД + загруженных файлов вне хоста, контроль успеха, тест восстановления; TLS reverse proxy, rate/size limiting, наблюдение за доступностью и алертинг. Не добавлять новые общие рекомендации вместо выполнения измеримого восстановления.

## Элементы, которые не следует удалять как «ненужные» без доказательств

- `backend/app/services/Manrope-*.ttf` — используются регистрацией/измерением шрифта и PDF; font assets имеют лицензионный файл в frontend resources, лицензию проверить для копий.
- `backend/data/templates/{tech,workspace,education}.pptx` — seed assets нужны стандартному приложению и Docker.
- `examples/` — вероятно демонстрация/приёмочные выходы; подтверждение назначения требуется до удаления.
- `frontend/dist/` — сборочный output, игнорируется Git и создаётся командой build; он не является source of truth.

## Предложенный порядок работ

1. Установить происхождение пяти UUID PPTX, документировать лицензию и убрать подтверждённый дубль.
2. Добавить CI для поддерживаемых Python версий, frontend tests/build и Playwright.
3. Выполнить staging-приёмку и восстановление резервной копии.
4. Добавить adversarial/визуальные regression fixtures для LLM, импорта и экспорта.
5. Провести CSS dead-code audit и оценку размера репозитория; оптимизировать только измеримые затраты.
