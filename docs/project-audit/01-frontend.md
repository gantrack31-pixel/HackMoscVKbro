# Frontend: результаты аудита

## Область проверки

React 19 + TypeScript + Vite. Просмотрены `frontend/src/api.ts`, `App.tsx`, `pages/Wizard.tsx`, `components/ExportPanel.tsx`, точка входа `main.tsx`, структура CSS, package scripts и существующие тесты.

## Подтверждённые сильные стороны

- API-запросы централизованы в `src/api.ts`; session cookie не копируется вручную, CSRF добавляется централизованно.
- В `Wizard.tsx` реализованы отмена ожидания при размонтировании, восстановление активной задачи через `sessionStorage`, retry и тайм-аут ожидания.
- Экспорт проверяет HTTP-ошибку, использует имя файла с очисткой опасных символов и отзывает временный object URL.
- Есть проверки геометрии маркеров аудита и восстановления/retry генерации.
- `pnpm test`: 10/10 успешны; `pnpm build`: TypeScript и сборка прошли.

## Замечания и рекомендации

### FE-1. Слабое покрытие регрессиями UI и ключевых маршрутов — P1

**Основание:** в `frontend/tests/` обнаружены два набора Node unit-тестов. В `frontend/e2e/` есть Playwright сценарии, но Playwright в этой сессии не запускался. Unit-тесты в основном проверяют вспомогательную геометрию/текстовые контракты, а не поведение компонентов в браузере.

**Риск:** навигация с несохранёнными изменениями, доступность диалогов, обновление сессии, ошибки загрузки/экспорта и мобильные состояния могут регрессировать без отказа unit suite.

**Исправление:** включить `pnpm test:e2e` в CI на чистом Chromium с артефактами при падении; добавить E2E для истёкшей сессии, сетевой ошибки, неуспешного экспорта и восстановления незавершённой генерации. Для публичной матрицы браузеров добавить хотя бы smoke-набор на целевых движках.

**Готово, когда:** обязательный E2E job выполняется на каждом PR, не использует пользовательскую БД и сохраняет trace/screenshot при отказе.

### FE-2. CSS накапливался слоями — проверить, не удалять вслепую — P2

**Основание:** отслеживаются 22 CSS-файла; `src/main.tsx` импортирует 11, а страницы/компоненты добавляют локальные импорты. В частности, большие `workspace.css`, `refinements.css`, `experience.css` и `wizard-modern.css` содержат накопленные стили. Сам размер и название не доказывают дублирование.

**Риск:** каскад и порядок загрузки становятся неочевидными; мёртвые селекторы усложняют изменение интерфейса.

**Исправление:** построить список всех `import` и селекторов, проверить дубликаты/мёртвые правила статическим анализатором, затем переносить по компонентам небольшими PR. Снять скриншоты критических страниц до/после.

**Готово, когда:** каждый оставшийся stylesheet имеет понятного владельца, порядок импорта зафиксирован, а визуальные сценарии и production build проходят.

### FE-3. Извлечение ошибок API допускает предположение о форме detail — P2

**Основание:** `src/api.ts`, `request<T>`, для массивного `detail` предполагает элементы с `msg: string`, иначе общий fallback. Backend намеренно скрывает validation details, но другие FastAPI/провайдерные ошибки могут иметь структуру отличного формата.

**Риск:** пользователь увидит пустое/непонятное сообщение при ошибке нестандартной формы. Это не подтверждённый сбой для текущих типизированных ответов.

**Исправление:** нормализовать API error в общий тип: проверять каждый элемент, обрабатывать строки/объекты и статус/корреляционный ID, не выводя stack trace или чувствительное содержимое.

**Готово, когда:** unit-тесты покрывают строковый detail, массив, неизвестный JSON и непарсируемый ответ.

### FE-4. Ключ проекта в localStorage общий для браузерного профиля — P2

**Основание:** `App.tsx` хранит `deckly-active-project` без привязки к user ID, очищает его при logout и удаляет при отказе загрузки. Серверная авторизация при запросе проекта остаётся барьером доступа.

**Риск:** при переключении аккаунтов может возникнуть лишний запрос чужого ID/сброс последнего проекта. Нет основания считать это обходом серверной изоляции.

**Исправление:** хранить ключ с суффиксом идентификатора аккаунта либо очищать активный проект при смене пользователя и при неуспешной авторизации; тестировать последовательную смену двух пользователей.

**Готово, когда:** переход аккаунт A → logout → аккаунт B не пытается открыть сохранённый у A ID и не показывает его данные.

## Доступность и адаптивность

В проекте есть skip-link, клавиатурные проверки и E2E сценарии доступности согласно `docs/VALIDATION.md`. Результаты этих более ранних прогонов не являются независимым повторным измерением этой сессии. Планово проверить WCAG-контраст, фокус/возврат фокуса, screen reader labels, zoom 200%, ширины 320/430 px и `prefers-reduced-motion` на актуальной сборке.
