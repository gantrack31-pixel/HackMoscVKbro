# Шаблоны и импорт материалов: результаты аудита

## Область проверки

`services/templates.py`, `template_context.py`, `pptx_security.py`, `materials.py`, начальные ресурсы `backend/data/templates/`, Docker seed templates и tracked-файлы Git.

## Подтверждённые сильные стороны

- Загрузка PPTX ограничена по размеру и ZIP-ресурсам; XML разбирается с отключёнными внешними сущностями/сетевым доступом.
- Импорт TXT/MD/CSV/DOCX/PDF/PPTX ограничен количеством/размером файлов и суммарным текстом; сканы без текста получают предупреждение.
- Стандартные Docker seed templates отделены от пользовательского хранилища; пользовательский файл не должен перезаписывать исходник.

## Подтверждённые инвентаризационные замечания

### TM-1. Пять PPTX с UUID отслеживаются Git, их роль нужно установить — P1 до чистки

**Основание:** в `backend/data/templates/` отслеживаются UUID-файлы `6f0f57fb-…`, `76ab5183-…`, `aed8adb0-…`, `b15ef8aa-…`, `c3bdbb7b-…` наряду с тремя штатными шаблонами. Текущие `.gitignore` исключают новые произвольные `*.pptx`, но уже отслеживаемые файлы остаются в репозитории.

**Дублирование:** Git показывает одинаковый blob SHA у `76ab5183-…` и `c3bdbb7b-…`; это точное совпадение содержимого.

**Неизвестно:** являются ли UUID-файлы необходимыми fixture/образцами, являются ли пользовательскими загрузками или опубликованы с согласия правообладателя. Не удалять без проверки тестовых ссылок, происхождения и лицензии.

**Решение:** сопоставить каждый файл с тестом/демо, зафиксировать лицензию/источник. Если дубль не имеет намеренного отдельного назначения, оставить одну копию; если это пользовательские данные, убрать из истории Git по установленному процессу и подтвердить, что нет секретной/личной информации.

**Готово, когда:** для каждого binary asset указаны owner, source/license,用途/тестовая ссылка и причина хранения; точные дубли удалены только после подтверждения.

### TM-2. Параметр размера и лимит импорт-пакета различаются по scope — P2

**Основание:** `config.py` задаёт `MAX_UPLOAD_MB` (дефолт 50) и `/api/health` сообщает его. `materials.py` задаёт 5 MiB на документ, до 8 документов, сумму 15 MiB и 50 000 символов. Это может быть корректно: endpoint импорта материалов имеет собственные более строгие границы.

**Рекомендация:** собрать таблицу лимитов по каждому upload endpoint (PPTX-шаблон, аватар, импорт пакета), определить применимость `MAX_UPLOAD_MB`, показывать UI согласованное значение и тестировать превышение каждого лимита.

**Готово, когда:** документация и клиентский текст точно соответствуют серверному валидатору каждого endpoint.

### TM-3. Парсинг неизвестных PPTX имеет ограниченную fidelity — ограничение

Анализатор извлекает тему, макеты и выборочные объекты/слайды; он не обещает полное сохранение SmartArt, анимации и сложных мастеров в других форматах. Сохранять предупреждение о необходимости открыть результат в PowerPoint.

## План проверки материалов

- Заархивировать benign и hostile fixtures: повреждённый ZIP, слишком много частей, высокая степень сжатия, внешний relationship, DTD, путь с traversal, очень крупный XML, encrypted Office/PDF, повреждённый DOCX.
- Проверить безопасную очистку временных файлов при ошибке и исключение имени файла из path traversal.
- Проверять, что тексты и исходные файлы не записываются в логи без явного разрешения.
- Установить право/лицензию на включённые VK PPTX и примеры; не делать вывод о лицензии только по публичному происхождению бренда.
