# Архитектура

Браузер React → HTTP API FastAPI → сервисы Python → SQLite и файлы PPTX. LLM вызывается только Python-сервером.

`DeckContent` содержит заголовок презентации и 1–30 слайдов. Каждый слайд имеет заголовок, текст, тезисы, тип, данные диаграммы/таблицы, цитату и заметки. JSON проверяется Pydantic; диаграммы принимают только конечные числа и равное число значений/подписей.

Парсер шаблона читает ZIP/XML, тему, шрифты, пропорции, мастера и placeholder-поля. Генератор выбирает пригодный макет с заголовком и содержанием, нормализует координаты к ширине 1280 и создаёт сцены A/B/C. Имена и объекты исходного PPTX сохраняются в копии; оригинал не перезаписывается. Все три варианта используют один `DeckContent`.

Таблицы SQLite: users, sessions, oauth_states, auth_attempts, templates, favorites, projects, jobs. У пользовательских проектов, шаблонов и заданий есть user_id. Встроенные темы общие. Маршруты проверяют владельца перед чтением, экспортом и изменением. Старые записи без владельца не выдаются новым пользователям.

Пароли: scrypt N=32768, r=8, p=1, индивидуальная случайная соль. Сессионный токен — случайные 256 бит; в БД хранится SHA-256. Cookie HttpOnly/SameSite=Lax, срок 7 дней. Изменения требуют CSRF-токена; сторонние Origin отклоняются. Яндекс OAuth использует PKCE S256, state и привязку к браузеру. OAuth-токен профиля не возвращается в браузер и не сохраняется после получения пользователя.

Фоновые задания ограничены семафором до двух, состояние сохраняется в SQLite. При перезапуске незавершённые задания помечаются ошибкой. Для нескольких процессов/серверов следующий шаг — отдельная очередь задач и общее хранилище; текущая сборка запускается одним процессом.

PPTX: python-pptx, текстовые блоки, native charts/tables. PDF: ReportLab. HTML: самостоятельные SVG-сцены с встроенным шрифтом. Manrope используется для измерения строк и предпросмотра; в PPTX устанавливается шрифт шаблона. Поэтому визуальная сверка с PowerPoint обязательна для окончательной сдачи.
